# Исправления установщика уведомлений

Требования ревью 35626a2:

1. Первая установка с `--notifications` завершается, если реальный дочерний процесс
   `codex plugin add` меняет config.toml. Записи Codex сохраняются: после add установщик
   перечитывает файл, строит правку [tui] и сверяет запись с новым снимком.
2. Правки TOML валидируются tomllib до записи. Уже заданные `tui.notifications = ...`
   и `tui = {...}` требуют ручного перехода к [tui]; установщик отказывает до add
   и до изменения файлов. Остальные значения конфигурации сохраняются.
3. При первом включении запоминается только исходная строка notifications (либо её
   отсутствие) и факт добавления [tui]. Повторные установки не заменяют этот снимок.
   `--no-notifications` и uninstall восстанавливают исходное значение, сохраняя
   остальные настройки и изменения Codex. Если пользователь самостоятельно изменил
   notifications после установки, его новое значение сохраняется.
4. README сообщает, что заголовок вкладки может содержать текст первого запроса
   Codex. Сырые события и транскрипты для текста баннера не читаются; заголовок не
   сохраняется в кэше статусов.

Python 3.9 остаётся достаточным для базового плагина. Изменение native TUI settings
для уведомлений требует Python 3.11+ со стандартным tomllib; на старом Python
установщик явно отказывает до изменений.

План проверки:

- Сначала воспроизвести дефекты тестами: subprocess Codex CLI с настоящей записью
  config.toml, отказ для dotted/inline TOML, enable/disable/uninstall и повторная
  установка. Функцию run в новых интеграционных тестах не подменять.
- Исправить чтение после add, безопасное преобразование TOML и сохранение/возврат
  исходной настройки, добавить взаимоисключающие CLI-флаги.
- Проверить заголовок баннера, который содержит название вкладки из первого
  запроса; исправить README и SECURITY.md.
- Прогнать make test, проверить diff, обновить версию для нового кэша и закоммитить
  исправления только в notifications. Штатный install.sh и codex-no-daemon не менять.

Старые экспериментальные установки восстанавливают снимок только из пары
settings.json (уведомления ещё не включены) и config.toml/codex-config.toml в одном
каталоге резервной копии. Без подтверждённой пары установщик отказывает и предлагает
ручное восстановление; текущее false не выдаётся за исходную настройку.
